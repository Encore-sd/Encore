# XIAO AV Net app

Fork of `av_app` for the XIAO ESP32S3 Sense running `av_wifi_sta/av_wifi_sta.ino`.
Instead of the phone joining the board's network, the board joins **your** WiFi
(home WiFi or a phone hotspot), so the phone keeps its normal internet and cellular data.
Installs alongside `av_app` (package `com.example.xiaoav.sta`, shown as "XIAO AV Net").

- **Set up WiFi:** a pop-up (`WifiSetupModal.js`) lists the WiFi networks the board
  itself can see (it scans over Bluetooth, `boardSetup.js`; 2.4 GHz only), the user taps
  one, enters its password, and the board joins it. The board only runs Bluetooth while it
  isn't on a WiFi network (it halves the WiFi frame rate), so setup works on a new board
  or after forgetting.
- **Connect:** tries the board's saved address, then `xiao-av.local`, then asks the board
  over Bluetooth, then falls back to the board's own `XIAO-AV` network (`192.168.4.1`).
- **Forget WiFi** (while connected), or holding the board's B button for 3 s: the board
  forgets its WiFi and restarts on its own network, ready for setup.
- Streaming, preview and recording work the same as `av_app`.

> **Android only:** the live preview is a native Android view (`modules/jpeg-preview`), so the app won't build for iOS.

## Dependencies

### Tools to install on the PC

| Tool | Why | Notes |
|---|---|---|
| [Node.js](https://nodejs.org) LTS (24.x) | Installs the JS packages, generates the Android project, and bundles the JS during every Gradle build | `winget install OpenJS.NodeJS.LTS`. Restart Android Studio after installing it so Gradle can find `node`. |
| [Android Studio](https://developer.android.com/studio) | Builds the app and installs it on the phone | Includes the Android SDK and the JDK that Gradle uses (Gradle JDK = the bundled `jbr`). The SDK platform and build tools the project needs are downloaded on the first sync. |
| Android phone with **USB debugging** on | Runs the app | Settings → About phone → tap *Build number* 7 times, then Developer options → USB debugging. Accept the "Allow USB debugging" prompt when you plug it in. |

### JS packages (`package.json`)

Install with `npm ci` in this folder. To add or upgrade packages, use `npx expo install <package>` so the versions match the Expo SDK.

| Package | Purpose |
|---|---|
| `expo` (SDK 58), `react`, `react-native` | App framework |
| `expo-status-bar` | Status bar styling |
| `react-native-tcp-socket` | TCP connection to the board. It has **native code**, so the app can't run in Expo Go. It must be built as a native app (see below). |
| `buffer` | Node-style `Buffer` for parsing the board's binary packets |
| `expo-file-system` | Writes recordings into the folder you pick (native module) |
| `react-native-ble-plx` | Bluetooth for the WiFi setup (native module). Its config plugin in `app.json` adds the Bluetooth permissions, without location on Android 12+. |
| `patch-package` (dev) | Re-applies `patches/` after every install. The patch fixes a crash in `react-native-tcp-socket` 6.4.3 when a connection fails before it starts (e.g. Connect pressed while not on the board's WiFi). |

### Generated Android project

The `android/` folder is generated by Expo from `app.json` and is not checked in (see `.gitignore`).
Don't edit it by hand. Change `app.json` or `plugins/` instead and regenerate it.

`plugins/withEmbeddedDebugBundle.js` makes debug builds include the JS bundle. Without it, the app
would need a dev server on the PC, which the phone can't reach once it joins the board's WiFi.

## Recordings

Like `av_receiver.py`, each recording (Start/Stop in the app, or B on the board) is saved as
one `.mkv` holding the board's JPEG frames and 16 kHz mono audio, synced by the board's
timestamps (written by `recorder.js`). Files are named `av_YYYY-MM-DD_HH-MM-SS.mkv`.

The first time you press Connect, the app asks you to pick a folder (e.g. Movies or Download).
Recordings are saved there, and the folder is shown on screen. Use **Change** to pick another folder.
The `.mkv` files play in VLC on the phone or PC. Audio isn't played live in the app.

## Running on the phone from Android Studio

One-time setup (and after any change to `package.json`, `app.json` or `plugins/`):

```bash
npm ci
npx expo prebuild -p android    # add --clean to regenerate from scratch
```

Then:

1. In Android Studio choose **File → Open** and open the **`av_app/android`** folder (not `av_app`).
2. Wait for the Gradle sync to finish.
3. Select your phone in the device dropdown and click **Run ▶**.

JS changes in `App.js` are picked up on the next Run. For live reload while the phone is still on
USB, run `npx expo start` and `adb reverse tcp:8081 tcp:8081`. The debug build uses the dev server
when it can reach it and falls back to the bundled JS when it can't.
